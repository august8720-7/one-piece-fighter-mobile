# 手机联机接口与实施0927

沿已批准Goal实施：移动端复用桌面确定性core与四角数据，新增输入、连接和表现层；不引入权威服务器或修改战斗数值。

## 配对与同步

先验证 PeerJS 1.5.5 WebRTC 数据通道。PeerServer Cloud只交换随机房间/连接标识、SDP与ICE候选（含连接所需网络信息），不发送源素材、用户账号或游戏存档；对局输入在两端直连。默认 `iceServers: []`，不使用TURN中继或付费STUN；真实手机能否在当前Wi-Fi/热点直连必须实测。两端应先加载并校验本场资源，再同时开始。信令服务不可用时明确报错/重试，不能写成对局已连接。

采用有限输入延迟的锁步：初始共享4个空输入帧，此后仅双方同帧输入齐备时推进一步。每帧只采样并发送一次将来第4帧的本地输入；等待时保留尚未采样的触控锁存，不用预测补输入。迟到恢复后继续逐帧，不直接按墙钟补算整段战斗。每60帧比较同帧世界状态与RNG状态校验。此校验用于检测不同步，不是反作弊承诺。

长时间断线/版本冲突/非法数据/状态不同步应停止该场，提供重新配对并开新局；不能称无损恢复旧比赛。短暂停顿若原通道仍在且输入随后到齐，可以继续。暂停/切后台清理触控，双方都因缺输入而等待，界面要说明状态。

导出明确的input/hash/halt消息类型及解析校验。角色/种子/就绪/重赛握手由主代理在连接协调层处理。过期session数据不得污染新局；重复同帧不同输入、非法位、无界未来帧或同帧hash不一致必须明确失败。测试应覆盖丢/迟/乱序、跨局、越界、不同步及真实FightSim两端输入回放一致，不能只复刻实现。
